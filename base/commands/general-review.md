description: Spawn a Sonnet subagent to review non-code changes (docs, content, standards, letters, config)
---

对**当前变更做通用审查**——用于文档、内容、标准文件、生成的信件/摘要、配置等**非纯代码**的变更。流程与 `/code-review` 相同,只是关注点不同。

## 做法

1. **确定审查范围**(按此优先级):
   - 若 `$ARGUMENTS` 给了文件/目录/范围,审查它。
   - 否则用 git 取未提交变更:`git diff HEAD`;若为空则 `git diff main...HEAD`。
   - 若都为空,告诉我没有可审查的变更并停止。

2. **spawn 一个 Sonnet subagent**(`Agent` 工具,`model: sonnet`)做审查。给它:变更内容、相关文件完整上下文、以及本项目 `CLAUDE.md` 里的规则和标准(若存在)。

3. subagent 以**对抗式**心态审查,重点找:
   - **准确性**:事实/数据是否正确,与来源一致,无编造
   - **合规 / 标准符合**:是否符合项目 Standard 文档的规则(格式、措辞、字段、脚注约定等);本项目含 PHI 时,检查 PHI 处理规则(只留本地、身份标识优先级、SSN 策略、Human Gate)
   - **一致性**:术语、格式、结构是否与现有样例/模板一致
   - **完整性**:是否有遗漏的必填部分、未处理的边界情况
   - **清晰度**:表述是否有歧义、误导,或对读者(护士/医生/审计)不友好
   - **安全 / 隐私**:是否泄漏不该外传的敏感信息

4. **输出格式**——发现按严重度分组,每条包含 `文件:位置`、问题、以及**具体修复建议**:

   ```
   ## 🔴 HIGH
   - `path/to/doc.md:L12` — <问题> → <修复建议>

   ## 🟡 MEDIUM
   - ...

   ## 🟢 LOW
   - ...
   ```

   无发现的档次省略。全部通过则明确说"未发现问题"。

5. **只报告,不改内容**,除非我在 `$ARGUMENTS` 里明确说 apply/fix。
